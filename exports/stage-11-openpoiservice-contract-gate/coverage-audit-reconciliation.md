# 第59号覆盖审计口径统一说明

第58号出现两套数值，是因为它们回答不同问题，不能互相覆盖。

1. `coverage-audit-canonical.json` 是 V2 在武汉 UTM 投影内，以未序列化的完整双精度内部叶片做的审计。它验证算法本体：未覆盖为 `0.000000000000e+00 km²`，外溢为 `2.661157623152e-13 km²`，面积差为 `-2.046363078989e-12 km²`。
2. `coverage-audit-provider-roundtrip.json` 是把实际会进入 OpenPOIService payload 的 WGS84 GeoJSON 进行 JSON 序列化、反序列化、再投影后得到的审计。它验证载荷表示：未覆盖为 `2.141246300703e-05 km²`，外溢为 `2.862149947359e-05 km²`，重叠为 `1.077751221601e-10 km²`，面积差为 `7.209141813291e-06 km²`。

两层都在 1.903245962858 km² 的 0.1% 容差内，`withinTolerance=true`。后续报告必须分别引用 Canonical 层证明算法覆盖，用 Provider round-trip 层证明实际发送的几何载荷误差；不得再将任一层笼统写成“覆盖为0”。所有值均保留完整 JSON 双精度与科学记数显示字段。
